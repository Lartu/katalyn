LSPL complete reference

A practical and implementation-aware guide to the entire LSPL language: syntax, semantics, native facilities, shipped standard library, command-line interface, and the small surprises that matter in real programs.

C++ implementation · September 2026

01 Introduction

LSPL is a small interpreted scripting language created by Lartu. It favors a compact vocabulary, semicolon-terminated statements, dynamically typed values, one-based array conventions, associative tables, and block endings written as ok;. The current interpreter compiles source to Nambly VM instructions in memory and immediately executes them.

This manual documents the behavior of the current C++ implementation in this repository. It combines the historical manual, both earlier HTML manuals, the compiler and VM source, the command-line program, and the bundled stdlib.lspl. Where an implementation detail differs from an intuitive or documented intention, the difference is called out explicitly.

A first program

# Every statement ends in a semicolon.
$name: accept("Your name: ");

if len($name);
    print("Hello, ", title($name), "!");
else;
    print("Hello, mysterious stranger!");
ok;

The language at a glance

  • Values are numbers, Unicode text, tables, immutable byte sequences, opaque worker PIDs, or the internal nil value.
  • Variables begin with $; assignments use :.
  • Tables serve as dictionaries, arrays, sets, records, and lightweight objects.
  • Functions are declared with def; all arguments arrive in the table $_.
  • Blocks end with ok;, not braces.
  • The standard library is written in LSPL and embedded into the executable at build time.
  • There are no classes, modules, booleans as a distinct type, or a source-level nil literal. Runtime errors use try, catch, finally, and raise.

02 Build and run

Build

A C++17 compiler and make are required. From the repository root:

make
./build/lspl examples/disan_count.lspl

The executable is build/lspl. Useful maintenance targets are:

CommandEffect
makeCompile the interpreter and embed the current standard library.
make testBuild and run the language, standard-library, CLI, import, and file-I/O regression suites.
make run SCRIPT=file.lsplBuild if necessary, then run one script.
make cleanRemove the generated build directory.
make installInstall lspl in /usr/local/bin by default. Override with PREFIX or DESTDIR.

Run source

lspl program.lspl one two three
lspl -a 'print("Hello from an argument!");'
printf 'print("Hello from standard input!");' | lspl -s
lspl -n program.lspl

The normal form loads the bundled standard library before the program. -n omits it. -a runs the next argument as source text; -s reads source from standard input. Arguments after the selected source are available to LSPL as $_args.

Portable scripts. A Unix script may begin with #!/usr/bin/env lspl. The line is harmless to LSPL because it begins with #.

03 Source and lexical rules

Statements and whitespace

Every command and assignment ends with a semicolon. A newline is ordinary whitespace, so a statement can span lines and several statements can share one line. Function argument lists and expressions do not use semicolons internally.

$message:
    "one statement over several lines";
print($message); print("second statement");

Comments

# A single-line comment runs to the newline.

(* A multiline comment.
   It may contain (* another comment *) inside it. *)

(** This historical documentation style is simply a nested comment. **)

Multiline comments nest. In the current tokenizer, an unterminated multiline comment silently consumes the rest of the file instead of reporting an error.

Identifiers and variables

  • A command or function identifier begins with an ASCII letter or underscore, followed by ASCII letters, digits, or underscores.
  • A variable is $ followed by one or more ASCII letters, digits, or underscores. Unlike ordinary identifiers, the first character after $ may be a digit.
  • Names are case-sensitive: $name, $Name, and $NAME differ.

Number literals

Source number literals are unsigned decimal integers or decimal numbers with digits on both sides of the point: 0, 42, 3.14. Negative values use the unary minus operator. Forms such as .5, 1., hexadecimal, and scientific notation are not source literals.

Text literals and escapes

Text is delimited by double quotes and may physically span lines. The recognized source escapes are:

SourceValue
\nNewline
\tHorizontal tab
\"A double quote
\ followed by whitespaceConsumes that run of whitespace; useful as source line continuation.
Any other \xProduces x; the backslash is discarded.
Backslashes. There is no dedicated \\ escape. An unknown escape loses its backslash, so represent paths with forward slashes where possible.

Tokens and punctuation

The language recognizes parentheses, square brackets, braces, commas, assignment colon, arithmetic and logical glyphs. The two-character glyphs are >=, <=, ::, <>, !=, //, &&, and ||.

Brace access is shorthand for a quoted key: $person{name} means $person["name"]. The contents are static text, not a variable or expression. $table{} addresses the empty-text key.

04 Values and conversion

The six user-visible kinds

There is no separate Boolean kind. The bundled library declares $true as 1 and $false as 0. With -n, those names are absent unless the program declares them.

Nil and existence

There is no nil literal. Use is(expression) to ask whether a value is non-nil and unsafe($name) when probing a variable that the compiler cannot prove exists.

if is($record{optional});
    print($record{optional});
ok;

unless is(unsafe($possibly_undeclared));
    print("No value");
ok;

Implicit conversion

Equality

  • Two text values compare exactly as text.
  • Otherwise, scalar values compare numerically where conversion is possible.
  • Numeric equality uses a very small floating-point tolerance.
  • Tables compare identity, not contents. Two variables are equal only when they refer to the same table object.
  • Byte sequences compare by contents. Bytes and non-bytes are unequal; neither is coerced.
  • PIDs compare by worker identity and are unequal to every non-PID value.
  • Nil is unusual: any equality involving nil is false, even nil against nil. Any inequality involving nil is true.

Nil truth table

Nil represents absence rather than an ordinary comparable value. A missing table key is used below to produce it because LSPL has no nil literal.

OperationResult

nil = nil0
nil != nil1

if !$source{missing};
    print("The value is absent");

05 Variables and scope

Declaration and reassignment

# `in` is optional.
in $answer: 42;
$name: "Ada";

# The same syntax reassigns an existing variable.
$answer: $answer + 1;

# Assignment is a command, not an expression.
set($answer, 99);  # `set` provides expression-like assignment.

The compiler tracks declarations in source order. Reading an unknown variable is a parse error, even if a similarly named value might exist at runtime. A declaration encountered inside a conditional branch is considered known after that point at compile time, although the branch may not execute and the runtime value may therefore be nil.

Scopes

Top-level variables are global. A function call creates one local variable scope. Control-flow blocks do not create scopes. A read inside a function checks the current local scope, then globals. An ordinary assignment inside a function creates or updates a local variable; use global to write the global instead.

$counter: 0;

def tick;
    global $counter: $counter + 1;
    $temporary: "local";
    return $counter;
ok;

Unset

unset($a, $b) removes variables. At runtime each name is removed from the current scope if present, otherwise from globals. The compiler also forgets those names, so a later ordinary read requires redeclaration or unsafe.

Magic variables

Precedence

LSPL follows the conventional mathematical/programming hierarchy below, from tightest to loosest:

  1. ^
  2. Prefix ! and unary -
  3. *, /, //, %
  4. +, binary -
  5. &
  6. ::, <, >, <=, >=
  7. =, <>, !=
  8. &&
  9. ||
Examples. 2 + 3 * 4 is 14, 1 || 0 && 0 is 1, and -2 ^ 2 is -4. Parentheses always override precedence.

Power is right-associative, so 2 ^ 3 ^ 2 means 2 ^ (3 ^ 2). Other binary operators at the same level are left-associative. Power binds more tightly than unary negation, following mathematical and Python convention; a negative exponent such as 2 ^ -2 is accepted. Function calls, indexing, and parenthesized expressions bind as units. There is no unary plus and no ternary operator.

Short-circuit evaluation

&& evaluates its right operand only when the left operand is true. || evaluates its right operand only when the left operand is false. The result is always the normalized number 0 or 1, rather than one of the original operands.

# Safe guard:
if is($config{path}) && len($config{path}) > 0;
    print($config{path});
ok;

Because the skipped operand is not evaluated, it produces no function calls, assignments, process activity, file activity, or runtime errors. Compilation still parses and validates both operands.

07 Tables, arrays and indexing

Tables are the universal collection

$person: table;
$person{name}: "LSPL";
$person["year"]: 2026;

$numbers: arr(10, 20, 30);
append($numbers, 40);

$seen: dataset("red", "green", "blue");
if "green" :: $seen;
    print("present");
ok;

Keys are converted to text. Braces contain a literal key; brackets evaluate an expression. Reading a missing key yields nil. Nested assignment is supported when intermediate values are tables.

Array convention

An “array” is simply a table with consecutive text keys "1", "2", and so on. Function arguments, command-line arguments, arr, array, split, and explode follow this convention. Nothing prevents sparse, zero, negative, or named keys, but many library functions assume a dense one-based sequence.

References and mutation

Tables have reference semantics. Assigning a table to another variable does not copy it; both variables point to the same object. Mutation through either name is visible through the other. prototype makes a shallow copy: the outer table is new, but nested tables are still shared.

$a: arr(1, 2);
$b: $a;
$b[1]: 99;
print($a[1]);          # 99

$c: prototype($a);    # new outer table

Scalar indexing and substrings

Text and numbers can be indexed as their text representation. Text uses Unicode code-point semantics: positive indices are one-based and return one complete UTF-8 code point. Index 0 also returns the first code point. Negative indices count backward from the end, so "á猫🙂"[-1] is "🙂". Any index beyond either end returns empty text.

Unicode semantics

LSPL stores text as UTF-8 and lazily caches code-point boundaries. Consequently, len, indexing, substr, and for operate efficiently in Unicode code points rather than bytes. The cache is built once per text value and shared by copies.

$text: "á猫🙂";
print(len($text));           # 3
print($text[2]);             # 猫
print(substr($text, 2, 2));  # 猫🙂

A code point is not necessarily one user-perceived character. A decomposed e followed by a combining accent has length 2, and the joined family emoji 👨‍👩‍👧‍👦 has length 7. LSPL does not normalize canonically equivalent spellings. Malformed UTF-8 is tolerated: each invalid byte is treated as one independently indexable unit so file and process data cannot crash text operations.

Iteration order

for iterates keys. Numeric-looking keys come first in numeric order; other keys follow in lexical order. Iterating text or a number’s text representation yields indices 1 through its Unicode code-point length. During each iteration, $_r is the current key/index.

Rendering

Printing a table shows a map-like diagnostic representation. Storage uses ordered keys, so display order is lexical rather than array-numeric order; for example, key "10" may display before "2". Cyclic tables should not be printed because recursive rendering has no cycle detector.

Collection operations

  • len($table) returns entry count, not highest numeric key.
  • $key :: $table tests key presence, even if the stored value is false.
  • keys($table) returns a new dense one-based array of key text in lexical storage order.
  • del($table, $key) removes an entry in place and returns the table.
  • set($table[$key], $value) assigns a place and returns its new value.
  • A table literal constructed from function arguments cannot contain an internal nil/iterator value.

08 Functions

Declaration and calling

def greet;
    $name: "world";
    if is($_[1]);
        $name: $_[1];
    ok;
    print("Hello, ", $name);
    return len($name);
ok;

$length: greet("LSPL");

A definition has no parameter list. All arguments are placed into the local one-based table $_, making every function naturally variadic. There are no formal arity declarations or default-parameter syntax; test optional arguments with is($_[n]).

Return

return expression; exits with a value. Bare return;, or reaching ok; at the end, returns nil. A return may appear inside nested flow blocks and exits the function immediately.

Local state and context

Each call receives a fresh local scope containing $_, $_caller, and $_context. Ordinary assignments are local. Explicit global assignments update shared state. Recursion is supported by the VM’s call frames, subject to memory and stack limits.

Definition order and shadowing

Forward calls are supported: the compiler reserves a label and connects it when the definition is encountered. Every called function must be defined by the end of compilation. Redefinition remains source-position-sensitive: existing calls keep the older body and later calls use the new one.

Calls are expressions

Native and user calls can be nested and used wherever a value is expected. Arguments are comma-separated. A trailing comma is currently accepted, but leading or doubled empty arguments are errors; portable code should omit trailing commas.

09 Control flow

Conditional blocks

if $score >= 90;
    print("excellent");
elif $score >= 60;
    print("pass");
else;
    print("try again");
ok;

unless is($optional);
    print("missing");
ok;

if and elif execute on a truthy condition. else has no condition. unless executes when its condition is false. An if chain has one final ok;. A stand-alone unless also ends with ok;.

Loops

FormBehavior
while expression;Repeat while the expression is truthy.
whileis expression;Repeat while the expression is non-nil; unlike while, zero and empty text still count as present.
until expression;Repeat while the expression is false.
for expression;Iterate the expression’s keys or scalar Unicode code-point indices, placing the current key in $_r.
 
$i: 1;
while $i <= 3;
    print($i);
    $i: $i + 1;
ok;

for $person;
    print($_r, ": ", $person[$_r]);
ok;

whileis read_line($file);
    print($_r);  # the condition result is available here
ok;

Loop control

  • continue; skips to the next iteration of the nearest loop.
  • break; exits the nearest loop.
  • break 2; exits two nested loops; the depth is a source number, not a runtime expression.
  • ok; closes the current function or control block according to the compiler’s block stack.

Conditions and iteration update $_r. Because it is shared magic state within the scope, nested conditions and loops overwrite its previous value; copy it to a named variable when it must survive nested work.

Errors and guaranteed cleanup

try;
    $data: read_bytes("settings.bin");
    if !len($data);
        raise("The settings file is empty");
    ok;
catch $error;
    print($error{kind}, ": ", $error{message});
finally;
    print("cleanup always runs");
ok;

A try must have catch $variable;, finally;, or both. The catch variable is an error table containing at least kind, message, file, line, and pc. raise(text) creates an Error; raise(table) preserves custom fields and fills missing standard fields.

finally runs after normal completion, after a caught or uncaught runtime error, and while return, break, or continue leaves the protected block. This is the difference from placing code after the construct: ordinary following code is skipped by those abrupt exits, whereas finally runs during the exit. A return or new error inside finally replaces the earlier return or error. exit() terminates the process immediately and does not run finally blocks.

09A Concurrency and workers

LSPL uses an actor-style concurrency model. Every worker has an isolated VM runtime and a private FIFO inbox. Workers do not share mutable variables; they communicate by sending copied values to PIDs. Scheduling is automatic—there is no yield() function and no cooperative action required by programs.

Starting and addressing workers

def echo;
    $envelope: receive();
    send($envelope{from}, $envelope{message});
    return "finished";
ok;

$worker: spawn(echo);
send($worker, "hello");
$reply: receive();
print($reply{message});
$result: wait($worker);

The first argument of spawn is a bare LSPL function name, checked by the compiler—not quoted text and not a first-class function value. Remaining arguments become the new function’s ordinary $_ arguments. spawn returns an opaque PID. self() returns the current worker’s stable PID; the original program is worker 1 and has an inbox like every spawned worker.

Messages and inboxes

send(pid, value) synchronously copies the value into the destination’s FIFO inbox and returns 1. Receiving removes exactly the oldest envelope:

$envelope: receive();
$sender: $envelope{from};       # PID
$message: $envelope{message};   # the copied value

receive() blocks indefinitely. receive(seconds) blocks for at most that duration and returns nil on timeout; receive_now() never blocks and returns nil for an empty inbox. A nil message is not confused with a timeout because a delivered nil remains inside a non-nil envelope.

Numbers, text, bytes, nil, PIDs, and tables may be sent. Tables are deep-copied at send time, preserving repeated references and cycles within the copy. Consequently, later sender mutations and receiver mutations cannot race. Bytes are immutable and may safely share storage. Internal iterator values cannot cross worker boundaries.

Isolation

At spawn time, the worker receives a deep snapshot of the parent’s global variables. It then has independent globals, local scopes, stacks, exception handlers, and open-file registry. Changing a global or table in one worker never changes it in another. Path strings can be sent, but a text file opened in one worker is not automatically open in another.

Completion, timeouts, and failures

worker_alive(pid) is true until the worker returns or ends with an uncaught error. wait(pid) blocks for completion; wait(pid, seconds) returns a timeout result if necessary. Waiting never consumes inbox messages and may be repeated.

StatusResult table
done{status} is "done"; {value} contains the function’s copied return value.
error{status} is "error"; {error} contains the structured uncaught error.
timeout{status} is "timeout"; the worker continues running.

An uncaught error ends only the spawned worker. The root worker retains normal CLI behavior: its uncaught error ends the program. A worker may spawn and wait for other workers. Waiting for oneself and sending to a finished or unknown PID are catchable runtime errors.

Lifetime and current backend

When the root source reaches its end normally, lspl waits for every spawned worker to finish. A worker left forever in receive() therefore keeps the program alive; use an explicit stop-message protocol. exit(status) remains a whole-process operation.

The current backend maps each LSPL worker to a native C++ thread. Inbox waits use condition variables, so blocked workers do not poll or consume CPU. Console output and process environment are process-wide resources; concurrent printing may interleave, so applications commonly designate one worker for output.

See examples/concurrency.lspl for a complete counter actor.

12 Processes and time

External commands

$status: exec("printf 'hello'");
print("status: ", $status);
print("out: ", $_stdout);
print("err: ", $_stderr);

exec is synchronous: LSPL waits for the child process. It captures exact standard output and standard error, updates $_stdout, $_stderr, and $_exitcode, and returns the numeric exit code. Multiple arguments are concatenated with no inserted separator, so these two forms differ:

exec("printf ", "'hello'");  # compiler joins to: printf 'hello'
exec("printf", "'hello'");   # compiler joins to: printf'hello'

The command is interpreted according to the process library and host platform. Treat untrusted text as dangerous: LSPL does not provide structured argument escaping.

Sleeping

sleep seconds; pauses the current process. Fractions are supported; the runtime converts seconds to an integer number of microseconds.

printc("waiting...");
sleep 0.25;
print("done");

Clock and network helpers

datetime() reads the host’s local clock natively and has no shell-command dependency. The standard-library get_http and call_api helpers still invoke curl and depend on that command being installed.

13 Imports

import "helpers.lspl";
import "models/person.lspl";

An import path must be static quoted text. It is resolved relative to the file containing the import, not necessarily the process working directory. Imported source is compiled inline at the import location and shares global variables and function names with the importer.

  • There are no namespaces, export lists, or private declarations.
  • Imports are source-position-sensitive; imported definitions become available after the import.
  • There is no automatic deduplication. Importing a file twice compiles it twice.
  • There is no cycle detector; cyclic imports eventually fail or exhaust resources.
  • Because code is inline, name collisions and function shadowing follow normal source-order rules.

16 Command-line reference

OptionMeaning

Once a source file or argument-source mode has been selected, later tokens are program arguments—even if they begin with a dash. They become $_args[1], $_args[2], and so on. The CLI executes one program per process.

For a file-backed program, $_scriptpath contains the normalized absolute filename of the main script and $_scriptdir contains its absolute parent directory. Both are nil for -a and -s. $_wdir contains the absolute directory from which LSPL was invoked. Imported files do not replace either script-location value.

Standard library loading

Normally, stdlib.lspl behaves as though its source appeared before the user program. Thus its globals and functions are visible and may be shadowed later. -n is useful for the smallest runtime surface, VM/compiler testing, or programs that provide their own library.

17 Errors and diagnostics

The front end distinguishes tokenization, lexing, expression, and parse errors. Messages identify the source file and line. Runtime failures also include the instruction/program-counter location where possible.

PhaseTypical causes
TokenizerBroken string syntax or invalid character structure.
LexerMalformed variable, number, glyph, or unrecognized token.
Expression compilerMissing operand, unmatched grouping, unusable unary operator, or invalid call arguments.
Parser/compilerUnknown command, wrong native arity, reading an undeclared variable, bad block structure, or missing import.
Runtime/VMInvalid type conversion, arithmetic failure, unopened/unwritable file, invalid indexing, or external process trouble.

The compiler’s declaration checks are intentionally strict enough to catch many misspellings. unsafe bypasses only that compile-time guard; it does not suppress runtime errors. Compile-time errors cannot be caught. Runtime errors can be handled with try/catch; an uncaught error prints the traditional diagnostic and returns status 1.

Debugging techniques

  • Use is around optional keys and function arguments.
  • Print table values directly to inspect their keys and contents.
  • Run with -i to inspect generated compiler/VM instructions.
  • Use print("value=", $value, " len=", len($value)); for scalar diagnostics.
  • After exec, inspect all three process magic variables.
  • After opening a file, test is_open before reading or writing.

18 Nooks, crannies and limitations

This section deliberately records behavior that is easy to miss. Some items are useful rules; others are current implementation defects preserved here so programs can avoid them.

Language semantics

  • Semicolons, not line endings, terminate statements.
  • There is no nil literal, and nil does not equal itself. Use is for presence checks.
  • Nil is false in conditions and !nil is 1, but nil remains an absence sentinel: equality involving nil is always false and inequality involving nil is always true.
  • && and || short-circuit and normalize their result to numeric 0 or 1.
  • Operator precedence follows the conventional hierarchy documented above; parentheses remain useful when an expression’s intent is not immediately obvious.
  • Source numbers are stricter than runtime text-to-number conversion; runtime conversion currently accepts numeric prefixes.
  • Text length, indexing, substring positions, and iteration count Unicode code points—not bytes or grapheme clusters.
  • Index 0 aliases the first scalar code point; negative scalar indices count backward from the end.
  • Unicode normalization and full Unicode case conversion are not performed; case helpers transform ASCII letters only.
  • Tables compare reference identity. There is no built-in deep equality or deep copy.
  • Printing a cyclic table can recurse indefinitely.

Compilation and source order

  • Forward function calls are resolved when their definition appears; a missing definition is a compile-time error.
  • Redefining a function affects only calls compiled after the new definition.
  • Declaration tracking follows compilation paths, not runtime paths. A conditional declaration may be “known” but nil.
  • unset has both runtime and compile-time consequences.
  • Imports are inline, not modules, and have no deduplication or cycle detection.
  • An unclosed multiline comment consumes to end-of-file without a diagnostic.
  • A trailing function-call comma happens to be accepted but should not be relied upon.

Current native/library defects and surprises

  • The case-conversion library is ASCII-only.
  • The HTTP helpers depend on external Unix-style commands; datetime() is native.

Portability and resource behavior

  • The interpreter requires a C++17 toolchain to build; the resulting CLI has no Python runtime dependency.
  • External process syntax, available commands, path syntax, and exit statuses vary by host platform.
  • Table keys are stored as strings. Diagnostic storage order is lexical, while for gives numeric keys numeric priority.
  • Each interpreter execution owns its VM stack, scopes, labels, calls, exception handlers, and open-file registry. Handles close when that runtime is destroyed. Host environment variables and standard streams remain process resources.
  • Worker state and messages are isolated, but console streams, the process environment, and the operating-system process itself are shared resources.
  • The native-thread backend is practical for moderate worker counts, not Erlang-scale millions of processes.
Robust LSPL style. Define before use, keep arrays dense and one-based, probe optional data with is, use parentheses freely, use substr for end-relative text, verify files with is_open, treat shell input as trusted-only, and use the native JSON functions for strict parsing and correct escaping.

19 Grammar and cheat sheet

This is a readable structural summary, not a byte-for-byte parser specification. Ellipses mean repetition; brackets mean optional syntax.

program          := statement*

statement        := ["in"] place ":" expression ";"
                  | "global" place ":" expression ";"
                  | function_call ";"
                  | "if" expression ";" statement*
                    ("elif" expression ";" statement*)*
                    ["else" ";" statement*] "ok" ";"
                  | "unless" expression ";" statement* "ok" ";"
                  | ("while" | "whileis" | "until" | "for")
                    expression ";" statement* "ok" ";"
                  | "def" identifier ";" statement* "ok" ";"
                  | "try" ";" statement*
                    ["catch" variable ";" statement*]
                    ["finally" ";" statement*] "ok" ";"
                  | "return" [expression] ";"
                  | "break" [integer] ";"
                  | "continue" ";"
                  | "sleep" expression ";"
                  | "import" string ";"

place            := variable (index)*
index            := "[" expression "]" | "{" literal-key-text "}"

expression       := number | string | "table" | variable
                  | place | function_call
                  | "(" expression ")"
                  | "-" expression | "!" expression
                  | expression binary-operator expression

function_call    := identifier "(" [expression ("," expression)*] ")"
variable         := "$" (ASCII-letter | digit | "_")+
identifier       := (ASCII-letter | "_")
                    (ASCII-letter | digit | "_")*
number           := digit+ ["." digit+]
comment          := "#" text-to-newline
                  | "(*" nested-comment-text "*)"

Complete miniature program

# stats.lspl
def average;
    $total: 0;
    $count: 0;
    for $_[1];
        $total: $total + $_[1][$_r];
        $count: $count + 1;
    ok;
    if $count = 0;
        return 0;
    ok;
    return $total / $count;
ok;

$values: arr;
for $_args;
    if is_numeric($_args[$_r]);
        append($values, to_num($_args[$_r]));
    ok;
ok;

unless len($values);
    halt("usage: lspl stats.lspl NUMBER ...");
ok;

sort($values);
print("count: ", len($values));
print("lowest: ", $values[1]);
print("highest: ", $values[len($values)]);
print("average: ", average($values));

The word table is a value constructor. Native function names are listed in chapter 14; standard-library names are ordinary user functions.
